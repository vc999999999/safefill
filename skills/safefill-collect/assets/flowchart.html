一个提交，三层保护

群发模式：yintian-submission/3

① 信封头与个人认证

任务、邀请、模板哈希、公钥标识和算法信息。HMAC-SHA256 覆盖信封；认证后才登记与计数。

② 包裹本次数据密钥

RSA-OAEP-3072 / SHA-256，使用收集方任务公钥。

③ 加密填写内容与附件

AES-256-GCM；载荷包括字段、附件、告知、令牌，以及可选的授权候选。AAD 绑定任务与模板上下文。

密文并不隐藏全部元数据：文件名、信封头、群内发送者及发送时间仍可能可见。收件认证摘要也属于受保护数据。

Prompt 理解任务，Python 执行规则

两个文件夹均可独立安装 · Python 3.11+
两个 Skill 入口
Prompt

判断场景、补齐需求、解释流程，把敏感操作交还给本人。

  • 区分 HR 收集与员工填写，排除普通问卷、他人资料等场景。
  • 准备配置与分发文案；有明确授权及发送能力时执行发送。
  • 本人授权后使用宿主看图能力；识别结果只作为候选。
  • 不执行模板和图片里夹带的指令，不索取密码或保险柜值。
确定性执行层
Python

把取值、验证、加密和状态落到可检查的程序行为上。

  • 校验模板与身份；保险柜匹配只选择本次要求的字段。
  • 绑定候选与原附件，处理加密、认证、去重和提交版本。
  • 区分硬性错误、OCR 问题与运行故障，保留重试与审计。
  • 校验路径、系统锁与原子写；按最新通过状态生成 Excel。

collection.py

任务创建、密文收件、状态与复核、明文 Excel、加密交接、迁移和期限清理。

fill.py / vault.py

模板检查、本人保险柜、按需匹配、确认与封装。无需安装收集者文件夹。

evidence_routing.py

auto / local / agent / manual；限制候选结构、附件摘要和任务绑定，不调用网络模型。

review_evidence.py

Tk 本地证据窗口：图片缩放旋转、PDF 翻页、逐项确认；提交时再次核对状态与期限。

secure_io.py

受限权限、原子替换、路径组件与链接检查、系统文件锁；并发操作使用一致边界。

mcp_server.py

七个工具提供能力查询、收件、状态、进度报告、分发检查、催办与临时清理。

新版本不会悄悄覆盖旧结论

  • 最近提交、最近通过、待处理数分别维护v1 已通过，v2 待处理时，v1 结论保留用于追溯。
  • 当前 Excel 只纳入最新版本已通过的人v2 尚未通过时，不把 v1 静默当作当前结果导出；导出提示未纳入人数。
  • 人工结案保留操作证据记录版本、操作者、时间与固定原因码，普通重试不覆盖结论。

主流程与兼容入口分开

  • 新群发任务带个人认证凭据FORM.yintian-form 可公开；每人的凭据私下给本人，无凭据不能借身份提交。
  • 旧无认证群发任务继续只读不能迁移出过去不存在的认证。旧定向格式保留，数据库写入需要显式迁移。
  • 硬件依赖按需安装核心安装无需 RapidOCR / OpenVINO 或模型 API；模型与量化工具保留为可选入口。
