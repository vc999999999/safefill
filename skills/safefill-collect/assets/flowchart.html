SAFEFILL 4.2 · AGENT REQUEST WORKFLOW

人只对话，Agent 之间传请求包

HR Agent 把需求编译成机器请求包；员工 Agent 读取字段、通过对话填写并加密；HR Agent 收件并生成 Excel。默认流程没有人工 HTML 表单。

01 · HR说清需求用途、字段、必填性、截止时间、联系人
02 · 收集 Agent生成机器请求包REQUEST.yintian-request规范 JSON，不生成 HTML
03 · 员工 Agent读取、问齐、加密姓名-短码.yintian员工不打开或填写请求文件
04 · 员工本人发送只把 .yintian 交给 HR
05 · HR Agent统一汇总结果.xlsx + 结果-attachments/只纳入最新且通过校验的记录
姓名可见是明确设计。 姓名只用于外部文件名，便于 HR 整理；收集端不信任文件名，始终以解密载荷为准。手机号、身份证号等不得进入文件名。

数据与安全边界

回执内容

AES-256-GCM 加密；随机数据密钥由 RSA-OAEP-3072/SHA-256 包裹。信封头只有任务、请求结构摘要、公钥标识和随机回执编号。

HR 私钥

私钥文件始终加密；随机本地密钥以 0600 存在任务目录外。跨设备只能使用带独立密码的加密任务交接包。

附件

通过校验的附件解密到 Excel 同名目录，单元格写相对路径。默认不启用 OCR，避免识别环境阻塞普通材料收集。

更正

员工把本人上一次回执交给填写 Agent；新回执沿用随机编号，收集端保留历史并只导出最新通过版本。

开放请求包不是身份认证。 姓名由员工自报，不能防止同名、冒名或请求包转发。只有确需预先限定提交者时，才启用需要名单和逐人凭据的 group 兼容模式。

确定性闸门

填写前

  • 校验请求包格式、目标 Skill、公钥指纹、字段与告知摘要
  • 只使用员工当前明确提供的值和附件
  • 缺项、格式错误、越界或过期时不生成回执

导出前

  • 验证信封、解密认证、必填项、类型、附件哈希与内容
  • 异常和待复核记录不混入 Excel
  • 已有 Excel 或附件目录绝不覆盖
