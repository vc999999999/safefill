# SafeFill 五分钟演讲稿

沿用已确认的顺序：作品定位、协议与效率、工程分工及例子、隐私与 OpenVINO、Wiki、收尾。时间为排练预算，需结合本人语速调整。括号内提示不朗读。

## 0:00—0:30｜介绍作品与场景

大家好，我的作品是 SafeFill，一组面向多人信息收集的多角色 Skills 工作流组件。它希望在提高收集效率的同时，减少敏感资料的不必要暴露。

比如部门组织团建，HR 要收集订票和住宿资料。员工反复填写，HR 反复解释、核对，再把不同人的资料整理成表格。SafeFill 就从这个常见的办公动作出发。

## 0:30—1:20｜固定协议怎样提高效率

我发现，收集过程中有很多交流内容，其实每次都差不多：要哪些字段、按什么格式提交、缺项怎么办、更正后采用哪份。

所以，我把这些固定的工作约定和交接协议，沉淀成收集者与填写者两个 Skill。

HR 说明需求，Agent 生成请求包。员工把请求包交给自己的 Agent，复用本机已有资料，只补缺项，本人确认后生成加密回执。收集端再统一校验，导出 Excel。

请求和回执仍可以通过现有群聊交接。用户只需要表达需求、补充必要资料，不必先学会整套操作流程。

**协议固定下来，Agent 就有了稳定的执行依据，也降低了用户理解这项工作的成本。**

## 1:20—2:40｜工程分工与字段映射

实现时，我特别注意 Skill 与 Agent 的分工。

Agent 已经具备理解需求、调用工具的能力。Skill 要补充的是这个工作特有的规则。因此，入口指导怎么协作，references 存放协议说明，scripts 里的 Python 负责校验、加密和版本处理。

这些规则写成脚本，Agent 每次就能调用同一套实现，不必重新生成处理逻辑。

举个例子，请求写的是“联系手机”，保险柜里叫“本人手机号”，是否对应，需要 Agent 理解语义，再由本人确认。脚本检查映射的字段是否存在、类型是否兼容。

但“本人手机号”和“紧急联系人电话”类型一样，含义却不同，脚本不能直接替换。

再比如，新回执先到、旧回执后到，系统依据验签后的修订号选择当前记录，不让收件顺序决定结果。

**需要理解的地方发挥 Agent 的能力，需要一致执行的地方交给脚本。** 这是我设计这组 Skills 时遵循的边界。

## 2:40—3:50｜隐私与 OpenVINO

同样的分工，也用在隐私处理上。

Agent 推进任务，需要知道哪些字段缺失、下一步做什么，但不一定需要看到所有资料的完整内容。

所以，我增加了本地文本补录路径：用户把资料保存在本地，只提供文件路径。脚本调用 OpenVINO 本地模型提取字段，再做校验。完整结果留在本机供本人核对，主 Agent 只获取字段状态和核对文件路径。

我选择 OpenVINO，是看重它的本地部署与推理优化能力，希望利用已有设备完成提取，减少对云端推理服务的依赖。新增文本路径已完成流程测试，真实模型效果仍待实测。

收集端也一样：脚本在本机解密、生成 Excel，HR Agent 获取数量、异常和文件位置，HR 自己查看完整结果。

这条路径减少了明文进入主 Agent 上下文的机会。用户如果选择直接在聊天中补录，内容仍会进入模型。

## 3:50—4:40｜Wiki 与个人差异

协议可以固定，每个人的情况却不一样。因此，我为两个角色各保留了一份本地 Wiki。

收集者可以记录业务惯例，选取与本次目的有关的字段说明，带进请求包。填写者可以记录允许自己 Agent 读取的背景和偏好，原始 Wiki 不自动外发。

比如，有人希望参加团建时能带孩子，有人希望活动安排多一些休息。Agent 可以参考备注，提醒本人是否提出这些需求。

如果本次收集设有可选的“特殊安排需求”字段，本人确认后就能提交，供 HR 在本地结果中查看。组织者需要知道如何安排，员工可以自己决定是否说明私人原因。

**Wiki 帮助理解个人情况，协议继续约束资料怎样提交。**

## 4:40—5:00｜收尾

SafeFill 把重复的工作约定沉淀成协议，让 Agent 帮用户以更低的理解成本完成信息收集。

我希望好的 Skill 能接住具体工作，也能清楚地知道：哪些能力交给 Agent，哪些规则需要固定，哪些决定留给人。

谢谢大家。

## 使用提示（不朗读）

- 本稿按五分钟预算组织，尚未经本人实读计时；超时优先删去“新旧回执乱序”一段，保留字段映射例子。
- 对应现有 PPT：第 1—3 页用于开场与痛点，第 4—5 页说明工作流，第 6 页承载工程分工，第 7 页讲 OpenVINO，第 8 页建议改成 Wiki，第 9 页收尾。本次没有修改 PPT。
- Wiki 是允许本端 Agent 读取的明文备注，不应放具体证件值或不愿进入模型的私人细节。特殊安排示例依赖任务已经设置对应字段；当前没有将自由 Wiki 备注自动附送或让 HR Agent 读取明文总结的功能。
- 本地文本路径减少主 Agent 对明文的接触，不能泛化为全部输入路径都不可见，也不隔离同一系统账户下的恶意读取。
- OpenVINO 的设备支持和优化能力参考其[官方项目说明](https://github.com/openvinotoolkit/openvino)及[GenAI 说明](https://github.com/openvinotoolkit/openvino.genai)。本稿不宣称 SafeFill 已测得具体加速比、推理成本或所有设备兼容性。
