v3.3.0 · 双 Skill 闭环：收集端 yintian-skill × 填写端 yintian-fill · 四角色泳道：职能人员终端（人类专属）/ AI Agent · MCP / 员工浏览器 · 本机 / 数据资产

一、端到端主流程（11 个阶段）

职能人员 · 人类终端
AI Agent · MCP

1 准备
编辑 collection.json
  • 用途 / 截止 / 保存期限 / 联系人 / 更正方式必须真实具体
collection.py init-config
  • 生成配置模板；字段类型白名单（8 种确定性类型）
roster.csv（employee_id,name）
collection.json
2 创建
collection.py create --mode directed|groupTTY
  • RSA-OAEP-3072 任务密钥对
  • 随机任务密码 → scrypt + AES-256-GCM 包裹私钥（yintian-key/1 信封）
  • 密码写控制终端（/dev/tty），只显示一次，不进 stdout
  • directed：每人生成独立随机认证令牌（256 位，库中只存 SHA-256）+ INV-*.yintian-form JSON
  • group：无令牌，全员共用单份 FORM.yintian-form
tasks/YT-xxx/
├ task.json / private.pem.enc
├ state.sqlite3（0600）
├ invite-index.csv（0600）
└ invites/INV-*.html + *.yintian-form（directed）
　或 FORM.yintian-form（group）
3 分发
群发 yintian-form JSON（group）/ 按 invite-index 私聊逐人发送定向 JSON+HTML（directed）
  • group：FORM.yintian-form 无个人标识，可群公告分发
  • directed：INV-* 按人私聊，不得串发
distribute.py verify / messagesMCP
  • verify：校验邀请齐全、防 ../ 路径穿越
  • messages：按人生成防串发文案（只含文件名，不含绝对路径）
  • 只读名单级标识，不碰令牌与密文
收到邀请（directed 文件名不含姓名）或共享表单 JSON（group）
INV-*.html / INV-*.yintian-form 经私聊分发；FORM.yintian-form 经群公告分发
4 填写加密
双通道（产出同构 .yintian 信封）
  • 通道 A · yintian-fill Skill（有 AI 环境）：fill.py inspect 查看字段 → scan-idcard 本地 OCR → seal 加密封口，全程本机离线
  • 通道 B · INV-*.html（Chrome/Edge 兜底）：CSP 强制断网 default-src/connect-src 'none'；真伪核对区：任务编号 / 邀请编号 / key_id 公钥指纹；遮罩预览 + 告知确认后才允许导出
  • AES-256-GCM 加密字段+令牌+附件，RSA-OAEP 包裹数据密钥
  • AAD 绑定 格式版本/任务/邀请/schema哈希/key_id；group 模式无令牌，invite_id=GRP-<employee_id>
  • 导出后清空表单；附件 ≤5MB/个、≤15MB/份
.yintian 密文信封（≤32MB），两通道同构
5 接收
collection.py ingestMCP
  • 信封算法白名单防降级；拒绝符号链接
  • 兼容 group 信封：GRP-<employee_id> 无令牌，版本上限按工号计数
  • 整体 SHA-256 去重；每邀请版本上限 10（超限拒存）
  • 错误只记类型名，不泄露密文内容
  • 过期任务拒收；截止后提交标记 late
私聊交回 .yintian
submissions/INV-xxx/vN.yintian
6 复核
collection.py reviewTTY
  • getpass 询问任务密码 → 内存解密，全程不落盘明文
  • 校验完整性 / 令牌(恒定时间比对,directed) / schema+告知哈希绑定
  • group 无令牌：姓名与名单比对，不符只标记进人工复核（身份兜底）
  • 手机号正则、身份证 GB 11643 校验码+日期
  • RapidOCR + OpenVINO 复核证件附件（图片/扫描 PDF 内存渲染）
  • PDF 像素上限计入渲染缩放（防内存 DoS）
  • OCR 冲突只标记人工复核，永不自动覆盖手填值
state.sqlite3 更新状态/缺失/冲突字段名
（不存明文值、不存 OCR 原文）
7 协调
status / report / distribute pending / cleanupMCP
  • report：XLSX/JSON 数据最小化报告（工号+姓名+状态，无敏感值；防公式注入）
  • pending：筛选未交人员生成催办文案
  • cleanup：每阶段结束 dry-run 汇报；--apply 只删孤儿临时文件/死锁/pycache
  • 未经批准不打开、不上传、不转发报告
reports/progress.xlsx · progress.json（0600）
仍含姓名+工号，非匿名数据
8 导出交付
collection.py export-clearTTY
  • getpass 询问任务密码 + 输入任务 ID 二次确认
  • --fields 白名单逐列导出 · --mask last4|mid4 脱敏
  • --purpose / --recipient 必填（交付审计）
  • 明文 XLSX 仅本机落盘（0600）+ 显著明文警告；用后删除
  • 系统无法管控落盘后传播，如实告知
禁止：Agent 不得代跑 export-clear，不得经手密码、打开或转发明文产物
result.xlsx（明文，0600）—— 授权数据终点在职能接收方
9 查看
collection.py revealTTY
  • 重新问密码 → 显示单份明文 → 清屏；输出过滤控制字符防终端注入
禁止：Agent 不得启动/旁观/捕获 reveal，不得索要或接收任务密码
明文只存在于该终端内存
10 交接
export-task / import-taskTTY
  • 导出 yintian-task/3：内存打包 → scrypt + AES-256-GCM 整体加密
  • 一次性交接密码只显示一次，须另一渠道告知接收方
  • 篡改/密码错误 → GCM 认证拒绝，零落盘；KDF 参数上限防毒包 DoS
  • 兼容导入 v1/v2 明文包：显著告警 + 输入任务 ID 二次确认
task.yintian-task（加密信封 JSON，≤200MB）
11 到期
collection.py purgeTTY
  • 输入任务 ID 二次确认后删除任务目录，留匿名计数
  • 不擦磁盘残留；不删收件目录/交接包/备份（如实告知）
status 显示过期 → 停止接收，引导 purge 或新建任务
任务目录删除，仅存匿名计数

二、.yintian 密文信封结构（浏览器产出 → Python 解开）

外层信封（明文头）：format_version / task_id / invite_id / schema_hash / key_id / algorithms 白名单 / iv / encrypted_key / ciphertext
ingest 阶段只校验这一层：算法套件白名单防降级、base64 格式、尺寸上限——不解密、不碰内容
RSA-OAEP-3072 / SHA-256 包裹的 AES-256 数据密钥（encrypted_key）
只有持任务私钥 + 任务密码的人才能解开；平台与 AI 看到的只有密文
AES-256-GCM 密文载荷：字段值 + 认证令牌 + 附件字节
AAD 绑定 格式版本/任务/邀请/schema_hash/key_id —— 换任务、换邀请、换模板、换密钥都解不开；解密后再逐项比对载荷内外一致性

四、模块地图（收集端 scripts/，约 3800 行 + 填写端 yintian-fill/）

collection.py（1215 行）
核心：10 个子命令（含 create --mode directed|group 双模式、export-clear 明文导出）、加密基元（scrypt/AES-GCM/RSA-OAEP）、信封解析、SQLite 状态机、ZIP 交接包管线
TTY 门控 · 原子写 0600 · busy_timeout · 版本上限（group 按工号计数）
export-clear（collection.py 子命令）
唯一明文出口：getpass 密码 + 任务 ID 二次确认；--fields 白名单 + --mask last4|mid4 脱敏；--purpose/--recipient 必填
明文 XLSX 0600 落盘 + 显著警告 · Agent 禁代跑
yintian-fill/（填写端 Skill）
员工侧独立 Skill：fill.py（inspect / scan-idcard / seal 三命令）+ fill_extract.py；读 yintian-form/1 JSON 本机离线填写加密，产出同构 .yintian 信封
明文只在员工本机 · group 模式 invite_id=GRP-<employee_id>
ocr_engine.py
RapidOCR 懒加载封装；内存字节扫描，不落明文临时文件；EXIF 方向自动纠正
缺依赖时友好报错降级
openvino_runtime.py
OpenVINO 设备探测与会话补丁（CPU/GPU/NPU）；自定义模型目录回退
rapidocr-openvino 1.4.4 私有结构，已钉版
ocr_matcher.py
OCR 文本要素提取与比对：GB 11643 校验码+日期、手机号、姓名/住址匹配、置信度标记
值按字段类型匹配；附件按 front/back 整词判定
distribute.py
分发辅助：verify（防穿越）/ messages（--template、--out-csv 0600 防覆盖防链接）/ pending 催办
纯本地零网络；文案只含文件名
cleanup.py
阶段性清理：dry-run 默认；三类安全删除集（孤儿临时文件 24h+、pid 死锁、pycache）；删除前复查防 TOCTOU
永不删除用户数据；符号链接不跟随
mcp_server.py
MCP 7 工具，全部经 YINTIAN_VAULT_DIR 保险箱约束，返回路径相对化
stdio 本地子进程模式，非远程服务
privacy.py / config.py
vault 边界（resolve 后判定）、全局配置（模型目录/设备/版本上限等环境变量）
39 行，全项目最小信任件
quantize_ocr.py / benchmark.py
INT8：det/rec 逐通道权重压缩 + cls 校准量化；基准含预热与 FP32/INT8 一致率对比
M2 实测：一致率 100%，体积 15.4→6.2MB
invite_template.html
员工端单文件：CSP 强制离线、Web Crypto 加密、遮罩预览、真伪指纹区
无外链无网络调用
测试体系
收集端 5 个测试模块 89 用例 + yintian-fill/scripts/ 测试：pytest 收集 + 直跑入口 + run_tests.py 零框架自动发现（双 scripts/ 目录）
GitHub Actions CI（Python 3.11）已跑绿
